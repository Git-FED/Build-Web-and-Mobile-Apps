The mental model.

There are three layers: your live website, the native shell, and the platform packaging step. Web2App Studio helps you configure the middle layer without changing the first.

01 / 05
SOURCE

Your website

The HTTPS URL remains your canonical content source. Deploy it independently and let the app shell point to it.

SHELL

Capacitor or Electron

The shell supplies native window behavior, icons, status-bar space, and platform packaging.

OUTPUT

Installable artifacts

Configs, manifests, and commands you can inspect, commit, and build yourself.

RELEASE ROUTINE

A calm path
to shipping.

Use this order when you are ready to move from the console to a real release.

03 / 05
01

Test the live URL

Confirm HTTPS, responsive behavior, authentication expectations, and whether the target site permits framing.

02

Generate and review

Export the JSON files, read them before committing, and adjust the app ID before platform signing begins.

03

Build locally

Run the platform-specific sync or distribution command from your own environment where signing credentials remain private.

04

Publish deliberately

Use TestFlight, Play internal testing, or a desktop beta channel before broad release.
